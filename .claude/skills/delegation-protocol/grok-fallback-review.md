# Delegation protocol §7. Fallback reviewer: Grok Build (optional)

A third model family for the §2 fallback row: when the Codex route is unavailable for the standard review of a Claude-authored diff and the Grok Build plugin (`grok-build@xai-grok-build`) is installed, the review goes to Grok before diff-reviewer, so the second pass stays cross-family. Nothing else moves: the risk-path adversarial pass keeps its route (§2 fallback row), Codex-authored diffs go to diff-reviewer or a human, writing never goes to Grok, and the complementary diff-reviewer routes of §6 step 4 stay. An INVALID Codex verdict re-dispatches Codex (§6 step 7), never Grok. Grok runs on xAI infrastructure and reads the repository at the reviewed commit, not just the diff: dispatch only when everything committed there may leave the machine (CLAUDE.md Data boundary) - otherwise diff-reviewer. It is a fallback, never a Sol replacement - its calibration probe (2026-10-13) showed lower recall than Sol on the same diff.

1. **Readiness and consent**: `node <bridge> check --json` must report `ready: true`; anything else -> diff-reviewer. On native Windows Grok's read-only sandbox is not enforced (upstream #24, CLI 1.0.52), so a run there is the human's risk call: ask for an explicit OK for this run, saying why, and without it go to diff-reviewer. Elsewhere the sandbox is Grok's documented behavior (not measured here) and no per-run OK is needed. `<bridge>` is the plugin's `scripts/grok-bridge.mjs`: `/grok-build:review` is not model-invocable (`disable-model-invocation: true`), so the orchestrator drives the bridge directly - a declared coupling to an *internal* interface (verified against plugin 0.2.1 / Grok Build CLI 1.0.52, October 2026); re-verify its flags, the job payload, the session-record files and the tool allowlist of steps 3 and 5 on every plugin or CLI update.
2. **Isolate - and know the limits**: snapshot `git status --porcelain --untracked-files=all` of the user's working tree, then create a disposable detached worktree at the commit under review (`git worktree add --detach <temp dir> <commit>`) and run there - never in the working tree, on every platform; nobody edits the working tree while the review runs. The worktree holds the tracked files of that commit only - untracked files, gitignored ones such as an untracked `.env` included, are not in it, but a tracked file is, whatever the ignore rules say - so uncommitted work is committed first (the human's call) or goes to diff-reviewer. On the base branch itself, the base is the ref the change starts from (e.g. the last release tag). A worktree separates checkouts; it confines nothing - it shares the repository's objects and refs, and an unsandboxed tool can reach any path. Only an enforced sandbox confines the run; the tool control of steps 3 and 5 detects violations and stops or invalidates - it does not prevent them.
3. **Dispatch and tool control**: `node <bridge> review --background --base <base> --scope branch --cwd <worktree> --json`, capturing the `review-*` `jobId`; no parseable job ID = failed dispatch -> diff-reviewer. Never `--model`: it hangs headless (upstream #31, CLI 1.0.52); the review runs on the CLI default model. Effort follows the §5 pin logic: preflight `models.default_reasoning_effort` in the resolved Grok config (`~/.grok/config.toml`) - at `xhigh`, omit `--effort` and inherit it (not yet verified live - step 5 confirms what ran); unset, lower or indeterminate, pin `--effort high`, the bridge's cap (its allowlist is `low|medium|high`; the model catalog lists `xhigh` above it). Never `critique` (upstream #35). As soon as the job record carries its `threadId` (the Grok session ID), read that session's `tool_definitions.json` under `~/.grok/sessions/<encoded cwd>/<session-id>/`: every offered tool must be in the allowlist measured on the probe - `read_file`, `list_dir`, `grep`, `web_fetch`, `image_gen`, `image_edit`, `image_to_video`, `reference_to_video`, `enter_plan_mode`, `exit_plan_mode`, `ask_user_question`. Anything else - a shell tool (`run_terminal_cmd`), an editing tool, a sub-agent tool (`task`) - means `node <bridge> stop <job>` at once and diff-reviewer. This check runs after the start, not before it - nothing pauses the run meanwhile, so it limits exposure and step 5 still audits every call. (Grok's docs say its `explore` agent can run shell commands; the bridge's run on the probe was offered none. The control reads what was offered instead of trusting either.)
4. **Deadline**: 25 minutes, exactly one extension of the same length for a job still reported running, then `node <bridge> stop <job>` and diff-reviewer - the §6 step 5 rule. (Probe: ~9 minutes for a ~95 KB diff in one pass, no chunking.)
5. **Verify what ran**, from the same session directory: `summary.json` must show `sandbox_profile` read-only and `reasoning_effort` at least the ordered value; every `tool_call` update in `updates.jsonl` must name an allowlisted tool and carry `_meta."x.ai/tool".read_only: true` (a missing flag counts as false), with `signals.json` (`toolCallCount`, `toolsUsed`) agreeing; the worktree's `git status --porcelain --untracked-files=all` must be empty; and the user's working tree must match the step-2 snapshot. Any miss, or a file you cannot read, makes the verdict INVALID: do not classify its findings - go to diff-reviewer (no Grok re-dispatch). A call not flagged read-only, or a changed user tree, is also an incident: tell the human before anything else. These are tripwires, not proof - they show what Grok called and that both `git status` outputs are as expected, not that nothing else happened (a further change to an already-modified file, or a write to an ignored one, leaves the status line unchanged). Report the model from `current_model_id`: there is no ordered Grok model, since the bridge cannot pin one.
6. **Findings, report, cleanup**: validate and classify every finding per §6 step 6 - never auto-apply. Report the provenance as *verified* from the session record (model, effort, sandbox profile, session ID, job ID), the result verbatim, the classifications, every call other than `read_file`/`grep`/`list_dir` with its `rawInput` (a `web_fetch` URL can carry data out), and spend as the token counts in `usage.json` - never its cost field (no money in this repo). Remove the worktree and confirm the job is no longer running. The bridge has no path scoping: on a mixed-authorship branch Grok sees everything, but its pass discharges only the Claude-authored portion - the Codex-authored portion still goes to diff-reviewer (§3).
